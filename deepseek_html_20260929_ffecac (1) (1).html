Architecture note

This build is a single-file frontend. The recommended production topology is: FastAPI backend (forecast, observations, correction, verification, upload, exports endpoints) · Xarray + NumPy/Pandas for gridding and aggregation · scikit-learn / PyTorch for the correction models · PostgreSQL + PostGIS for district geometry and verified archives · Celery/Redis for ingestion and batch verification jobs · the same Leaflet + Chart.js frontend consuming the REST API.

Rainfall thresholds (IMD convention)

  • Rain day: ≥ 2.5 mm/day
  • Moderate: 15.5 – 64.4 mm/day
  • Heavy: 64.5 – 115.4 mm/day
  • Very heavy: 115.5 – 204.4 mm/day
  • Extremely heavy: ≥ 204.5 mm/day

Metrics

MAE mean absolute error · RMSE root mean square error, penalises large errors more · Bias mean(f − o), positive = over-forecast · CSI critical success index = H/(H+M+F) · POD probability of detection = H/(H+M) · FAR false alarm ratio = F/(H+F) · FBI frequency bias = (H+F)/(H+M) · Brier mean squared error of probability forecasts.

What is real vs simulated in this build

  • Real: all arithmetic — the correction, the ensemble, every metric, the CSV quality control, the exports.
  • Simulated: the weather itself. Rainfall, observations and regime states come from a seeded stochastic generator.
  • Not implemented: any trained ML model, SHAP, real IMD/NWP ingestion, flood modelling, data assimilation, authentication.

Limitations

Correction coefficients are hand-set illustrative priors, not fitted parameters. Regime classification is a heuristic softmax over synthetic indices, not a validated classifier. Verification statistics describe performance on generated data and carry no information about real forecast skill. None of the accuracy figures here should be cited.
